# Slice CI: make the gates run without being asked

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every gate this project has built runs automatically on every push, and **each one is demonstrated failing before it is believed passing.**

**Architecture:** GitHub Actions. The remote is `github.com/LackOfSkillz/worldbuilder-by-aetos`.

**Spec:** `docs/design/2026-09-02-mark-2-world-studio.md` §19 — DETERMINISM-001 as amended **explicitly requires CI and is currently unsatisfiable**, because there is no `.github` directory.

## Why this is a slice and not a chore

**Three things have gone wrong that CI would have caught, and each survived multiple commits:**

- The Python conformance suite **skipped silently and reported green while comparing nothing**, for a whole slice, because its engine guard is opt-in and nothing set it.
- The shipped `.wasm` was **several commits stale** and passing parity green — five differing bytes, all panic-location line numbers.
- The provenance guard that caught *that* was itself **unreproducible from git**, failing on every machine but its author's, and **survived six commits** because nothing ran it.

That last one is the argument in miniature: a gate nobody runs is a gate that can rot without anyone noticing. **All three are recorded in two ledgers already**, which is the sign a note should become work.

## Global Constraints

- **Nothing under `worldbuilder/` may be modified.** `worldbuilder/integration/maritime.py` has a pre-existing uncommitted change; leave it unstaged.
- **`cargo` is not on PATH in bash locally — use `/c/Users/gary/.cargo/bin/cargo.exe`.** In CI it will be on PATH; do not copy the local workaround into the workflow.
- **Verify by exit status, never by grepping `test result:` lines.**
- `.claude/worktrees/zen-lewin-cd32bf/` is a **full second checkout of this repo** — plain `grep -r` from the root double-counts.
- **Every figure names its population, its method with parameters, its host — and, for a ratio, its step.**

## The gates that must run

| Gate | Command | Why it exists |
|---|---|---|
| Engine, five configurations | `cargo test -p worldbuilder-engine` under `--no-default-features`, default, `--features python`, `--features wasm`, `--features python,wasm` | 409/0/5 in the first three, 439/0/5 in the last two |
| The determinism guard | included above (`no_std_math`) | bans `f64::` forms, `mul_add`, unmarked casts — **scans all of `src/`** |
| Python conformance | `pytest tests/` **with `WORLDBUILDER_REQUIRE_ENGINE=1`** | without that variable it **skips silently and reports green** |
| Provenance | `npm run check:wasm` | the shipped artifact matches the source it was built from |
| Parity | `parity_dump` then `parity.mjs` | 53,251 values native-against-WASM, 0 divergent |

**The Python suite needs the wheel built** — `maturin develop --release --features python`, or an equivalent. Note `pyproject.toml` declares setuptools as its backend while the extension is built by maturin: **the build is not reproducible from project metadata**, which is a third standing gap recorded in slice 1p's ledger. **If a task can close it cheaply while wiring CI, say so; do not silently restructure the build.**

### Task 1: The workflow

**Files:** Create `.github/workflows/`

Wire every gate above. **`WORLDBUILDER_REQUIRE_ENGINE=1` is not optional** — it is the difference between running the conformance suite and appearing to.

**Cache deliberately or not at all.** A cache that serves a stale `.wasm` or a stale `target/` would reproduce, inside CI, exactly the class of bug CI exists to catch.

- [ ] **Steps:** write it, push, watch a real run, commit.

---

### Task 2: Prove every gate can fail

**This is the task that matters.** A CI pipeline that has only ever been green is indistinguishable from one that runs nothing — and **this project has found eight broken verifiers by breaking things on purpose**, including a network trace that could not have shown traffic, a parser that read a missing section as "unknown", three checks that counted zero work as success, and a clone test that passed because its setting silently did not apply.

**For each gate, push a branch that should fail it, and confirm CI goes red for the right reason:**

- a `f64::` form or an unmarked cast → the determinism guard
- a changed constant → the engine suite
- an uninstalled or stale wheel → the conformance suite **fails rather than skips**
- a source edit without a rebuild → provenance
- a mutated `.wasm` → parity

**Record the run URL and the failure message for each.** A gate whose failure nobody has seen is a gate nobody knows the shape of.

- [ ] **Steps:** one failing branch per gate, record each, restore, commit.

## What this slice must NOT do

- **No restructuring of the Python build** beyond what CI needs. The setuptools/maturin split is a real gap, but changing a build backend under a working conformance suite is its own slice.
- **No browser automation** unless Task 1 finds it cheap. Playwright in CI is a weight decision, not an afterthought.
- **No changes to any gate's behaviour.** This slice makes existing gates run; it does not make them stricter.
