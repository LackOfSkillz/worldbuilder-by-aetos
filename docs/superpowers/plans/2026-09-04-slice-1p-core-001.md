**Goal:** Give the Rust core a data model that accommodates the stream graph — nodes, receivers, drainage areas, lakes — so slice 5 **populates** it rather than **restructures** the engine. Plus the feature gate and generator-version constant that this and slice 2 both need.

**Architecture:** A `StreamGraph` in struct-of-arrays form, a flat binary format with a section table and a fail-closed reader, and a `World` holding a `Surface` and an `Option<StreamGraph>`. **`Surface` is not touched.**

## THIS IS THE FIRST SLICE WITH NO PYTHON ORACLE

Every previous slice compared against a running Python reference, so "correct" meant "bit-identical to the thing that already worked". **There is no Python stream graph.** `grep` for `receiver`, `drainage`, `watershed`, `catchment`, `downhill` across `worldbuilder/` finds only `coast_walk.py` and `demo.py`, neither of which is one. (Search trap: grepping `lake` returns six files, **all of them `blake2`**.)

**So the tests must assert PROPERTIES, not equality.** That is a different discipline and it is easier to get wrong. Four properties are the backbone, and all four were measured true during extraction:

1. **The receiver relation is a strict forest** — no cycles. Verified by peeling: 20,000,000 of 20,000,000 nodes peeled at the largest size tried.
2. **Roots partition cleanly into mouths and lakes**, exactly as §14.2 claims — a non-boundary root *is* a lake.
3. **Rebuilds are bit-identical** for the same seed and parameters.
4. **Native and WASM agree** — graph construction was checked at 1,200,000 f64 values, zero divergent, with a **negative control** that diverged on 801,673 values when one constant moved 0.67%.

**A build that runs is not a build that works** — the 327-byte WASM module that exported only `memory` is this project's standing reminder. **The exercise must assert, not merely produce.**

## Three rulings, each departing from something

### 1. "Poisson-sampled" names the property, not the algorithm — use the existing spiral

§14.1 says "a geometric graph over Poisson-sampled points". **We are not implementing Poisson-disc sampling**, and the reason is not convenience:

- **It is definitionally sequential**, which `generation.rs`'s own module doc forbids in terms.
- **It is measurably less regular here.** A plain Fibonacci spiral holds a minimum separation of **0.872 x nominal at a million nodes**; Bridson's guarantees only *some* separation and gives no better.
- Nothing in Bridson needs a banned API — the blocker is not the constraint list, it is the architecture.

§14.1's stated reason for choosing this representation is that "Poisson points and Voronoi areas transfer to a sphere directly — no projection, no grid seam, no pole singularity." **That property is what matters, and a spiral with hashed jitter delivers it, is parallel, and is already conformance-tested.** So: **generalise the existing spiral-plus-hashed-jitter.** This is the one place the slice departs from the spec's literal words, and it is recorded here so a later reader sees the reasoning rather than an omission.

**The jitter constant cannot be reused.** The obvious setting is dangerously wrong: at 0.45 x spacing, two nodes landed **48 m apart on a 22.6 km lattice**, and the existing `JITTER_RAD` would be about **227 x the spacing** at planet scale. Cell areas vary 0.735–1.285 x ideal at the recommended jitter. **Measure and choose it; do not inherit it.**

### 2. No spherical Voronoi, and no lake overflow edges

**Do not build true spherical Voronoi cells.** It is a degeneracy-prone exact-predicate problem under DETERMINISM-001 and is a slice of its own. Store `area_m2` per node and compute it by a method this slice chooses and records.

**Do not build the lake super-graph's overflow edges.** Reserve the `outflow_lake` field, leave it at its sentinel. Slice 5 fills it.

### 3. VERSION-001 has no implementation, so fold its constant in here

**CORE-001 is currently insurance against a mechanism nobody has built.** VERSION-001 exists as one prose mention in a README; `version()` returns `CARGO_PKG_VERSION`, **which bumps for a docs fix**. A format that fails closed on an unsupported generator version needs a generator version that means something.

**So this slice lands the generator-version constant** — distinct from the package version — and the format header carries it.

## The minimum type surface, and what is safe to defer

**Must exist now**, because adding it later changes the meaning of what is stored:

- node count; positions (or a position checksum); `height_m`; **`area_m2`**; `receiver` with a **named root sentinel**; `drainage_area`; a **flags bitset**; a lake table keyed on root node with `level_m` and a reserved `outflow_lake`; an empty reach container; and a header carrying **generator version, seed, radius, node count, sampling kind and `sea_level_m`**.

**Three of these look optional and are not:**

- **`area_m2`** — omitting it silently changes the *meaning* of every stored drainage area.
- **the flags bitset** — without it an old graph cannot yield a water manifest at all.
- **`sea_level_m`** — the same graph means different things at different sea levels.

**Safe to add later without a bump:** everything in the lake super-graph except the root; thermal-correction state; uplift and erodibility (recomputable); everything derived from receivers; reach geometry; extra flag bits; and whole extra resolutions.

## Region-sliceability is forced, and it is a format decision now

**A 20 M-node graph is 1.45 GB of arrays and 2.16 GB peak RSS. It does not fit a 32-bit WASM heap under any field arrangement.** So the browser must load a *region* or derived primitives, never the planet.

**That makes region-sliceability a slice-1 format decision**, not a slice-5 optimisation — retrofitting it is exactly the kind of change VERSION-001 makes expensive. The section table must support reading a subset without parsing the whole file.
